# DeepL 客户端复刻方案 v1.0

> **状态：已实现，本文留作设计记录。** 按此方案落地的项目即 HsVerba 1.0（P0–P6 全部完成，P7 本地版不需要）。
> 与当初方案的差异：翻译引擎最终定为 OpenAI 兼容接口（而非方案里的三选一），并额外做了本地 whisper.cpp 语音字幕。
>
> 基于对 DeepL 26.9.1（131 MB，325 个程序集）的实际逆向结果编写。
> 本文件只描述方案，等待批准后再动手。

---

## 一、结论先行

**界面与交互 100% 可复刻，翻译引擎本身不可复刻。**

DeepL 的护城河是自研 NMT 模型（跑在 `w.deepl.com` 服务端），客户端里没有一行模型代码——它只是个会发 RPC 的壳。所以正确的复刻策略是：

- **客户端全量重做**（这是 90% 的用户体验价值所在，也是我们能 100% 掌控的部分）
- **翻译能力接外部引擎**（三条路线，见第三节）

这样做的产物不是"仿冒品"，而是一个**功能更全、体积小一个数量级、后端可自选**的同类工具。原版 131 MB，我们的目标 **12–18 MB**。

## 二、逆向得到的真实功能地图

从 `ViewModels.*.dll`（60 个）与 `Views.*.dll`（37 个）还原出的完整功能模块：

### 2.1 核心翻译

| 模块 | 功能 | 复刻难度 |
|---|---|---|
| `Translator` | 主翻译窗，源/目标语言双向，实时增量翻译 | 中 |
| `TranslationHistory` | 翻译历史、收藏、搜索 | 低 |
| `Models.Routing` | 文本路由（普通 / Pro 通道分流） | 低 |
| `Models.Localization` | 界面 30+ 语言 | 低 |

### 2.2 系统级集成（这块最影响"好不好用"）

| 模块 | 功能 | 技术实现 |
|---|---|---|
| `MiniDeepL.QuickTranslate` | 划词浮窗翻译 | `SharpHook` 全局鼠标钩子 + 剪贴板模拟 |
| `MiniDeepL.QuickWrite` | 划词改写浮窗 | 同上 + 流式 LLM |
| `Clipboard` | 剪贴板监听自动翻译 | Win32 `AddClipboardFormatListener` |
| `ContextualPopup` | 右键菜单 / 悬浮球 | 无激活分层窗口 `WS_EX_NOACTIVATE` |
| `Models.Shortcuts` | 全局热键 | `RegisterHotKey` / `global-hotkey` |
| `TrayIcon` | 托盘常驻、最小化到托盘 | `Shell_NotifyIcon` |
| `Notifications` | Windows Toast 通知 | `ToastNotifications` 等价实现 |
| `Theming` | 亮/暗主题跟随系统 | 系统 accent color API |

### 2.3 进阶功能（原版全部为 Pro 或受限）

| 模块 | 功能 | 依赖 |
|---|---|---|
| `DocTrans` | 文档翻译（.docx/.pdf/.pptx/.xlsx/.txt/.html）保留原格式 | OOXML 解包改写 + PDF 重排 |
| `ImageTranslation` | 图片翻译（框选区域、贴图覆盖原文） | OCR + 版面分析 + 图像修复 |
| `Ocr` | 屏幕截图 OCR（内置 Tesseract） | Tesseract 5 / PaddleOCR |
| `Speech` | 语音翻译（`NAudio.Wasapi` 回环捕获 → 字幕） | WASAPI loopback + STT |
| `Write` | AI 写作助手（改写/润色/语气调整） | LLM API |
| `Assistant` | 对话式 AI 助手 | LLM API |
| `Browser` | 内置 CEF 浏览器 + 划词扩展 | WebView2（比 CEF 省 80 MB） |
| `B2B` | 团队版：术语表共享、成员管理 | 后端多租户 |

### 2.4 基础设施

`Oidc`（OAuth2/OIDC 登录，对接 `auth.deepl.com` 的 authorize/token/introspect/revoke/userinfo/jwks 全套）、`Proxy`、`Preferences`、`OnboardingWizard`、`Statistics`、`FeatureGates` + `ABExperimentation`（远程特性开关）、`HiddenMenu`（内部调试菜单）、`Installer`、`Experiments`。

技术栈确认：**.NET 8 + WPF + CefSharp + gRPC + Serilog + OpenTelemetry + Sentry + Statsig + Polly + Tesseract + NAudio + SharpHook**。

## 三、翻译引擎：三条路线（需要你选一条）

这是整个项目唯一的关键决策点。

### 路线 A — DeepL 官方 API

- 质量：与原版**完全对等**（同一个模型）
- 成本：按字符计费，Free 档每月 50 万字符，Pro 档需订阅
- 延迟：国内直连不稳，通常需要中转
- 风险：你的产品本质变成"DeepL 的客户端"，受制于对方
- 适合：想立刻拿到一模一样的效果，不介意持续付费

### 路线 B — 第三方大模型 API（推荐）

- 质量：中英互译接近 DeepL，长文本和上下文连贯性更好；术语一致性和"信达雅"略逊
- 成本：可控，支持缓存 + 批量摊薄
- 优势：**Write / Assistant / 术语表统一用同一个引擎**，架构大幅简化
- 延迟：流式返回，首字延迟可压到 300 ms 内
- 适合：想做长期可用的产品

### 路线 C — 本地开源 NMT（NLLB-200 / Opus-MT）

- 质量：明显低一档，但**完全离线、零成本、零隐私风险**
- 体积：模型 600 MB – 2.5 GB（首次下载）
- 适合：涉密场景，或作为 B/C 的**离线兜底**

> **我的建议：B 为主 + C 兜底 + A 可选**。架构上把引擎抽象成 `TranslatorProvider` 接口，三条路线全部实现，用户可在设置里切换。这样任何一个引擎涨价或不可用，都不会让产品死掉。

## 四、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面壳 | **Tauri 2**（Rust） | 安装包 8–15 MB；系统集成全在 Rust 侧，原生性能；跨 Win/macOS/Linux |
| 前端 | React 19 + TypeScript + Tailwind + Zustand | 生态成熟，动效好做 |
| 全局钩子 | Rust `global-hotkey` + `rdev` | 无需管理员权限即可监听键鼠 |
| 屏幕捕获 | Windows Graphics Capture API | 比 BitBlt 快且支持 HDR/多屏 |
| OCR | PaddleOCR（中文强）+ Tesseract（兜底） | 中文识别准确率显著优于原版方案 |
| 音频 | Rust `cpal`（WASAPI loopback） | 系统声音捕获 |
| STT | `whisper.cpp` 本地 + 云端兜底 | 可离线 |
| 文档解析 | `docx-rs` / `pdfium` / `rust_xlsxwriter` | 保留原格式的关键 |
| 后端 | FastAPI（Python 3.13）+ PostgreSQL + Redis | 开发快，异步流式好 |
| 鉴权 | 自建 OIDC（对接你的账号体系） | 与原版同构，便于多端 |
| 分发 | Tauri Updater（增量更新） | 替代 Zero Install |

## 五、架构

```
┌─────────────────────────────────────────────────────────┐
│  Tauri 2 客户端 (Rust Core + React UI)                   │
│  ┌───────────┬───────────┬───────────┬───────────────┐  │
│  │ 主翻译窗   │ 划词浮窗   │ 托盘/热键  │ 文档翻译工作台 │  │
│  └───────────┴───────────┴───────────┴───────────────┘  │
│  ┌──────────────────────────────────────────────────┐   │
│  │ Rust 系统层：钩子 / 剪贴板 / 截屏 / 音频 / 通知     │   │
│  └──────────────────────────────────────────────────┘   │
│  ┌──────────────────────────────────────────────────┐   │
│  │ TranslatorProvider 抽象层                         │   │
│  │  ├─ DeepLProvider  ├─ LLMProvider  ├─ LocalNMT    │   │
│  └──────────────────────────────────────────────────┘   │
└────────────────────────┬────────────────────────────────┘
                         │ HTTPS / SSE 流式
┌────────────────────────▼────────────────────────────────┐
│  后端 FastAPI                                            │
│  OIDC 鉴权 │ 配额计量 │ 术语表 │ 文档队列 │ 历史同步 │ 缓存 │
└────────────────────────┬────────────────────────────────┘
                         │
              PostgreSQL ─ Redis ─ 对象存储
```

**流式翻译协议**：客户端每 300 ms 或遇句末标点就发一次增量请求，后端返回 SSE 分块，前端按句替换。这是还原"边打字边出译文"手感的关键，原版用 `Rpc.Ita.dll` 做同样的事。

## 六、分阶段交付（每阶段可独立验收）

### P0 · 骨架（约 2 天）
Rust + Tauri + React 工程，主窗口 UI 复刻（含亮暗主题），设置页骨架。
**验收**：双击启动，窗口跟原版视觉一致，< 20 MB。

### P1 · 核心翻译（约 4 天）
文本翻译、语言自动检测、流式增量、术语表、历史记录、复制/朗读。
**验收**：粘贴 5000 字英文，译文 1 秒内开始流出，术语表命中率 100%。

### P2 · 系统集成（约 4 天）
全局热键、划词浮窗、剪贴板监听、托盘、Toast 通知、开机自启。
**验收**：在任何应用选中文字按 `Ctrl+C+C`，300 ms 内浮窗出译文，不抢焦点。

### P3 · 文档翻译（约 6 天）
docx / pdf / pptx / xlsx / txt / srt，保留字体、表格、图片、页眉页脚。
**验收**：20 页带表格的 docx 翻译后，版式与原文件逐页对比无错位。

### P4 · OCR + 图片翻译（约 5 天）
框选截图 → OCR → 译文贴回原位，自动匹配背景色与字号。
**验收**：截一张英文 PDF 页面，译后可直接截图交付。

### P5 · 语音翻译（约 4 天）
系统音频/麦克风捕获 → 实时字幕浮窗 → 可选 TTS。
**验收**：播放英文视频，字幕延迟 < 1.5 秒。

### P6 · Write + Assistant（约 5 天）
改写、润色、语气切换、摘要、对话助手，全流式。
**验收**：选中一段中文，一键改写成商务/学术/口语三种语气。

### P7 · 账号与多端（约 5 天）
注册登录、订阅配额、云同步历史与术语表、设备管理。
**验收**：两台机器登录同一账号，历史与术语表实时一致。

**总计约 35 个工作日**（单人全职）。P0–P2 完成后已是一个可日用的工具（约 10 天）。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 翻译质量达不到 DeepL 水准 | 引擎可切换 + 术语库 + 后编辑规则，把差距控制在可接受范围 |
| 划词钩子被杀软拦截 | 走签名 + 白名单申请；提供"仅热键模式"降级 |
| 文档版式还原踩坑 | 用 OOXML 节点级替换而非整篇重排，先做 docx 再扩 pdf |
| API 涨价/断供 | Provider 抽象层已隔离，切换成本 ≈ 改一个配置文件 |
| 法律风险（界面过像） | 视觉上做自己的设计语言，不做像素级抄袭；功能对齐即可 |

## 九、需要你拍板的四件事

1. **翻译引擎**：A（DeepL API，效果对等但持续付费）/ **B（推荐，第三方 LLM）** / C（本地离线）—— 还是 B+C 双引擎？
2. **平台范围**：只做 Windows，还是 Windows + macOS 一起？（Tauri 跨平台几乎零额外成本，但测试要翻倍）
3. **交付形态**：先做 P0–P2 的"能用版本"给你试用，还是一次性做到 P7 全套？
4. **后端归属**：用我的方案自建（需要你提供服务器/域名），还是先做纯本地版（无账号、无同步，零服务器成本）？
